# JointCheck solder inspection — sampled review

## Scope and verdict

Repository: `knarayanareddy/jointcheck-solder-inspection`; pinned revision **`0fb7f9c90888c753a6d8f97595f1f3b26f0b3144`**; stage: implemented experimental prototype, not a production inspection system. Runtime, tests, images, provider, hardware and deployment were **NOT RUN**. Static source shows deliberate abstention and a separate scripted Pages demo; neither validates workmanship. Findings below are observations or bounded risks, not certification or a complete audit.

## Architecture and product boundary

The React entry point renders `App`; it probes `/health` and `/v1/info` and sends the selected photo to `/v1/inspect` ([main.tsx:1–10](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/frontend/src/main.tsx#L1-L10), [App.tsx:129–153,188–212](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/frontend/src/App.tsx#L129-L212)). FastAPI streams bounded JPEG/PNG input, calls OpenCV-backed analysis, optionally invokes an external vision endpoint, then returns an explicit non-actionable `UNDETERMINED` ([main.py:68–160](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/main.py#L68-L160)). The public gate evaluates caller assertions without setting the gate's trusted flag ([main.py:163–174](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/main.py#L163-L174)). The local JSONL runner and static Pages site are separate surfaces, not evidence of deployed photo inspection ([README:52–54,91–100](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/README.md#L52-L100)). Python, OpenCV/Pillow, FastAPI, React/Vite and an optional configured external model provider are dependencies; availability and provider contract were not verified.

## Findings ledger

**JC-01 — High, confirmed static, high confidence: production grading is intentionally unavailable.** The photo route declares `"verdict": "UNDETERMINED"` and `"actionable": False` ([main.py:139–158](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/main.py#L139-L158)). The README says zero labelled evaluation images and zero human-reviewed numeric rules ([README:6–16](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/README.md#L6-L16)); this is a repository claim, not an independently counted dataset. Contours are explicitly not segmented joints ([inspection.py:174–186,231–236](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/vision/inspection.py#L174-L186)). Do not release or reject assemblies using it. Preserve abstention until a qualified owner approves independently measured performance and rules.

**JC-02 — High, confirmed static, high confidence: intended measurements and rule contracts disagree.** The calibration test says `"no source rule is changed"`, then expects the wetting angle to return `measurement_provenance_invalid_or_incomplete`; it also documents excess/bridge metrics and missing schema quantities ([test_calibration_verdicts.py:63–102](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/tests/test_calibration_verdicts.py#L63-L102)). The gate requires measurement quantity to equal the selected rule metric ([gate.py:94–132](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/gate/gate.py#L94-L132)). This is a documented integration gap, not proof any particular threshold is correct. Agree on units, definitions and traceable rules with domain experts before implementing compatibility.

**JC-03 — High, unverified deployment risk, medium confidence: sensitive image and paid-provider exposure need a boundary.** The sampled app creates `FastAPI(...)` without a visible auth dependency ([main.py:12–19](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/main.py#L12-L19)), its inspection handler accepts `model_assist` ([main.py:75–80](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/main.py#L75-L80)), and the opt-in path invokes model assistance ([main.py:128–131](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/main.py#L128-L131)); the provider request sends base64 image bytes with `Authorization: Bearer` to the configured base URL ([vision.py:139–161](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/tf/vision.py#L139-L161)). If reachable without an external access control, callers could consume capacity and send images to the provider. Actual network exposure, proxy authentication, configured URL, retention and secret storage are unknown. Define authorization, provider allowlisting and data-sharing policy before external deployment; do not infer an existing compromise.

**JC-04 — Medium, confirmed static, high confidence: fixture tests are not in the sampled CI workflow.** The package defines `"test:fixtures"` ([package.json:6–11](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/frontend/package.json#L6-L11)); sampled CI runs backend tests and frontend build but not that script ([ci.yml:25–39](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/.github/workflows/ci.yml#L25-L39)). Script existence is not a passing result. The metadata records a [successful historical CI run](https://github.com/knarayanareddy/jointcheck-solder-inspection/actions/runs/40860904409) at the exact pinned SHA, not a current rerun or proof of domain accuracy. Add fixture and user-flow gates without weakening existing checks.

**JC-05 — Medium, unverified operational risk, medium confidence: bounded individual uploads still permit expensive concurrent work.** The API permits 10 MiB per upload and dispatches processing to a thread pool ([main.py:68–68,92–116](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/main.py#L92-L116)); inspection checks a 40-million-pixel ceiling before decode and then runs image processing ([inspection.py:196–205,212–236](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/vision/inspection.py#L196-L236)). No route-level concurrency or rate control appears in this sampled path. An external limit may exist; memory exhaustion and throughput are not measured. Load-test representative and hostile inputs and set limits at the deployment boundary.

## Five-discipline assessment

1. **Correctness / ML and domain:** abstention and finite/provenance checks are useful guardrails ([gate.py:79–88,109–137](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/gate/gate.py#L79-L137)). A hash and caller-set trust boolean do not prove a physical measurement; the internal geometry hook could use `trusted_measurement=True` when calibrated and computable ([inspection.py:139–167](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/vision/inspection.py#L139-L167)). The public photo route does not supply those hooks. Physical joints, lighting, lens distortion, calibration, class sensitivity, false negatives and inspector agreement remain unvalidated.
2. **Automation / testing:** the API tests assert prototype status and an unreviewed-rule abstention ([test_api.py:14–40](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/tests/test_api.py#L14-L40)); they were read, not run. CI history is not a hardware, security or held-out dataset evaluation.
3. **DevOps / operations:** snapshot metadata also records successful Pages deployment at the pinned SHA ([run](https://github.com/knarayanareddy/jointcheck-solder-inspection/actions/runs/40860904275)); serving state and workflow contents were not inspected. The batch container uses mutable `python:3.12-slim` and declares no non-root user ([Dockerfile:1–7](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/jobs/Dockerfile#L1-L7)). Release provenance, alerts, backups and recovery are unknown.
4. **OWASP / security:** JPEG/PNG signatures, streamed byte limits and pre-decode dimension checks are positive controls, not a full abuse assessment. Authentication/authorization and quotas are unverified outside the sampled app. Image content and model output are untrusted; response normalization restricts known IDs/types/codes but notes remain advisory ([vision.py:49–98](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/backend/app/tf/vision.py#L49-L98)). Provider URL/credential binding, prompt injection, logs, retention and tenant isolation need testing. Both ecosystem lockfiles appear in inventory; integrity and CVEs were not audited.
5. **UI / UX / accessibility:** default model assistance is off and requests are abortable ([App.tsx:116–127,188–209](https://github.com/knarayanareddy/jointcheck-solder-inspection/blob/0fb7f9c90888c753a6d8f97595f1f3b26f0b3144/frontend/src/App.tsx#L116-L127)). Pages fixture labels are explicitly synthetic per README; the rendered experience, keyboard navigation, screen-reader announcements, contrast, stale-response behavior and disclosure prominence are unverified. A checksum is not a signature.

## Blockers and owner decisions

Owner must select intended users and exposure, authorize data and provider sharing, supply approved credentials without exposing them, choose hosting and release/signing policy, and specify retention/restore needs. Qualified solder-workmanship reviewers must own rule provenance, capture hardware, labelling protocol and acceptance thresholds. No standards affiliation, certification, provider connectivity or actual hardware performance is established.
